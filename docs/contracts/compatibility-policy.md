# 兼容政策

## 兼容对象与边界

项目以 Android BookSource 的导入、规则求值、请求展开、搜索/发现/详情/目录/正文结果和失败/取消语义为主要兼容对象。`RssSource`、`ReplaceRule`、WebView、交互登录、段评写入、付费和外部事件只有在能力清单和对应宿主证据出现后才扩大承诺。reader-cli、reader-web 的用户、存储和交互行为属于应用边界，不把应用已有入口包装成 core 的统一 API。

## 证据等级

1. **Android 来源**：固定提交或页面快照中的源码、测试和行为注记，说明上游事实；不证明 TypeScript 已实现。
2. **源码事实**：当前 package/app 导出、实现和测试可以在本仓库复核；不等同 Android 对照通过。
3. **兼容证据**：脱敏 fixture、golden、跨端断言和稳定命令共同证明某一输入/输出；没有这些证据时标记待验证。
4. **部署证据**：具体 Node、Web、Edge 或生产配置下的取消、资源、用户隔离和恢复结果；不能从静态文档推导。

文档必须给出证据链接和限制。历史测试数量、源码存在、字段能够导入或静态规则能够编译，都不能单独标记为完整兼容。

## 已接受的共同要求

- 导入保留未知字段、原始文本和显式空值的差异；不因没有表单控件而丢失数据。
- 当前实现返回能力缺失、规则错误、请求失败、空结果、取消和资源清理等可判别状态，不把未实现能力伪装为空结果。
- core 只拥有平台无关规则与工作流；Node/Web 宿主拥有网络、Cookie、脚本、文件和部署策略；应用拥有用户范围、持久化、确认和删除清理。
- 安全限制（HTTP(S)、SSRF、预算、QuickJS、归档和日志脱敏）可以与 Android 存在有意差异，但必须登记在 compatibility，并保持诊断可见。
- 页面产出 URL 的 `{{...}}` 求值、动态 Header bridge 递归限制等已登记取舍不能在新文档中悄悄删除；改变它们必须有 Android 对照和迁移说明。

## 允许差异与变更

允许差异必须说明：Android 输入与结果、当前 package/app 行为、影响范围、为何保留、替代入口和补齐条件。优先在 `docs/compatibility/known-divergences.md` 维护差异，在 `status.md` 维护实现程度，在 `evidence-matrix.md` 维护证据，不在标准或 package README 再复制一份总表。

新增或修改公开行为时，先核对上游固定来源，再更新代码、测试和 compatibility 证据；涉及存储、用户状态、外部写入、取消或资源清理时还要更新应用/归档边界。未实现目标接口只能放在 archive，不能因为写进契约就成为 API。
