🥷 本文记录 Android 书源诊断页如何准备输入、占用调试通道、输出过程日志和查看四类原始响应，也记录批量书源校验的边界。

# 书源诊断

## 进入和书源恢复

入口是 `ui/book/source/debug/BookSourceDebugActivity.kt`。书源管理页和书源编辑页通过 URL 打开诊断页，`BookSourceDebugModel.init` 只按 URL 查询书源，不会修改书源。

加载完成后显示帮助输入：

- 搜索关键字，默认优先使用书源的 `checkKeyWord`。
- 书籍信息，默认使用当前搜索词。
- 目录，自动加 `++` 前缀。
- 正文，自动加 `--` 前缀。
- 发现入口，格式为 `分类标题::分类 URL`。

发现分类会调用 `bookSource.exploreKinds()`。首个有效分类填入帮助区，长按可以选择其他分类。发现分类出错时，帮助区显示错误，不会直接开始诊断。

## 输入前缀和执行流程

`BookSourceDebugActivity` 提交搜索词后：

1. 隐藏帮助区，清空旧日志列表。
2. 显示旋转加载。
3. `BookSourceDebugModel.startDebug` 尝试占用全局 `Debug` 回调通道。
4. 诊断模型调用 `Debug.startDebug`，日志按状态回调到适配器。
5. 状态 `-1` 或 `1000` 表示结束，隐藏加载；异常提示“调试失败”。

如果通道已被其他诊断占用，当前任务直接失败。模型销毁时调用 `Debug.cancelDebug`，避免回调继续写入已销毁页面。

## 过程日志和原始响应

普通状态日志按顺序追加到 RecyclerView。四类原始响应被单独保存：

| 状态 | 字段 | 菜单 |
| --- | --- | --- |
| 10 | `searchSrc` | 搜索原始响应 |
| 20 | `bookSrc` | 书籍信息原始响应 |
| 30 | `tocSrc` | 目录原始响应 |
| 40 | `contentSrc` | 正文原始响应 |

菜单打开 `TextDialog("html", value)` 查看原始文本。原始响应和过程日志的用途不同：日志说明规则执行到哪一步，原始响应用于判断请求是否返回正确页面、登录页、错误页或空 body。

## 诊断输入的实际含义

- 普通关键字进入搜索流程，规则解析结果和搜索原始 body 会被记录。
- 同一关键字进入详情流程时，使用搜索得到的书籍上下文。
- `++` 前缀要求诊断目录解析，帮助用户直接输入目录测试样本。
- `--` 前缀要求诊断正文解析。
- 发现分类不是普通关键字，必须保留标题和 URL 的分隔格式。

诊断页不会把原始响应自动转成“成功或失败”的结论，最终仍需结合日志、原始内容和书源规则判断是请求失败、登录状态失败、列表规则失败还是字段规则失败。

## 刷新发现分类和帮助

“刷新发现”会清理发现分类缓存、清空当前日志、重新显示帮助并再次读取分类。帮助菜单打开诊断说明。二维码扫描结果直接作为新的搜索输入。

## 批量书源校验

书源管理页的批量校验属于 `CheckSourceService`，不是诊断页的全局调试通道。用户选择书源和校验关键字后启动校验，页面保持常亮、显示 Snackbar 进度并允许取消。

校验会更新书源的 `checkStatus`、`checkDetail`、`checkedAt` 和响应时间。校验配置可以设置单源超时。普通搜索不会自动读取这些字段做禁用或降级，诊断页也不会自动修改启用状态。

## 对 CLI 调试功能的直接对照要求

CLI 至少应同时提供：

1. 当前阶段日志。
2. 搜索、书籍信息、目录、正文四类原始响应。
3. 请求 URL、最终 URL、状态码、响应头、耗时和解析输入。
4. 规则命中的字段级结果和空结果原因。
5. 运行中取消，以及调试通道占用提示。
