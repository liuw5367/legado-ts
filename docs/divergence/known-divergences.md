| 编号 | 主题 | 标准侧 | 实现侧 | 影响 | 策略 |

| D1 | 搜索与流程入口命名 | [搜索流程](../flows/search-flow.md) 的 `SearchRequest` / `SearchResultSink` / `SearchSourceStatus`（含 `stale`、`storage-error`），[阶段 C](../implementation/phase-c-workflows.md) 历史名 `searchOne` / `searchMany`，[阶段 D](../implementation/phase-d-extended-capabilities.md) 历史名 `searchOne` / `explore` / `getBookInfo` / `getChapterList` / `getContent` | `packages/source-core/src/index.ts` 导出 `searchBooks` / `discoverBooks` / `loadBookDetails` / `loadTableOfContents` / `loadChapterContent`，输入为 `SearchInput` 等，输出 `RuntimeResult` | 标准与流程文档中的入口名不能直接 `grep` 到代码；集成方按文档实现会失败 | 代码为准；文档已标注历史/目标名。若未来补齐多源 `searchMany` 或统一门面，先改代码再改标准 |
| D2 | 端口与宿主门面命名 | [宿主接口](../implementation/runtime-host-interfaces.md)、[阶段 B](../implementation/phase-b-rules-request.md) 的目标 `RuntimeHost` / `CallContext`，[目标 `OperationResult`](../implementation/runtime-contracts.md)（含 `stale` / `unknown` / `effects` / `changes` / `cleanup`） | `WorkflowPorts` / `ReadingPorts` / `NetworkHost`；Node 侧 `SourceRuleHost` / `SourceRequestHost` / `QuickJSJavaScriptHost` 等；流程结果为 `RuntimeResult<T>` + `WorkflowStatus`（无 `stale` / `unknown`） | 按 `OperationResult` 或 `RuntimeHost` 写适配层会类型错误；部分流程文档（[正文](../flows/content-flow.md)、[校验](../flows/source-check-flow.md)）仍描述目标保存 token 与 `checkSources` | 目标契约保留在 `runtime-contracts.md` / `runtime-host-interfaces.md` 并显式标注；新集成只依赖 `package-usage.md` |
| D3 | 能力清单中过时的“未实现”行 | [兼容矩阵](../quality/compatibility-matrix.md) 部分行仍写“未实现 runtime，待 fixture” | 导入/规则/请求/四类读取流程等已有实现与自动测试（`packages/source-core/tests/`、`packages/source-node/tests/`） | 读者可能把已实现但未跑 Android golden 的项误判为完全缺失，或把“已有实现”误判为“已验证兼容” | 已实现行改为“实现见 source-core/source-node…对照 fixture 待执行”；未实现能力（见 D4）保持未实现表述 |
